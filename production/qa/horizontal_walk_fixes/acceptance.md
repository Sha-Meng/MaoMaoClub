# 横向步态与拖动修复验收

日期：2026-10-17。引擎：Godot 4.6.3.stable.official.7d41c59c4；Windows，Compatibility / OpenGL，RTX 3060。

## 本轮结论

四项反馈均已修正；38 项单元及集成用例、1096 次断言通过，无失败。真实 GPU 渲染覆盖 54 个基础姿势、九位人物加服务员端盘共 80 个步态关键相位，以及 32 张连续中间帧。正式场景另运行 90 帧，引用约束、无边框、透明背景和原生置顶标志通过。

| 反馈 | 修复与验证 |
| --- | --- |
| 人物走路缺少脚步/手摆动 | 不再切换两张近似姿势或仅浮动身体；使用 45 个透明分件，双脚半周期交替，支撑脚按行进距离抵消位移，摆动脚抬起与屈膝，双臂反向摆动；端盘手稳定。验证等距离不同帧长、左右朝向、停止不踏步，以及全部分件非空。逐行检查实际渲染的接触、经过、抬脚与反向支撑阶段，并修正整身变形和腰腿锚点断开问题。 |
| 仅横向，无 Y 和纵深 | 自动移动、拖动过程、释放及旧档恢复均保持 Y=270；斜向及极端 Y 输入只改变 X；固定结构分层，不按 Y 排序或深度缩放。正式规则见设计归档。 |
| 调酒员可拖出店铺 | 模型拒绝独立拖动，指针阈值尝试不误触单击；吧台可见部分仍可单击资料；整体移动店铺会带动调酒员与挂点，旧档离岗员工回到店内。真实视口鼠标事件覆盖拒绝拖动、正常单击和斜向拖动。 |
| 拖空椅子突然出现人 | 拖动中的座位排除分配；未到达的预占顾客原地释放占用并重新找座，仅已入座顾客随椅子移动。覆盖拖动中新增顾客、仅一张空椅、释放后步行入座、预占椅和已坐椅；真实视口事件验证空椅拖动。 |

## 复现

```powershell
./tools/run_tests.ps1 -Render
./tools/run_desktop.ps1
```

- `unit_integration.json`：本轮单元/集成结果；含 30 分钟确定性营业、持续随机编辑、消费闭环、结算唯一性、检查点恢复与存档备份。
- `walk_cycle_gallery.png`、`walk_render.json`：80 个步态相位与渲染结果。
- `frames/walk_00.png` 至 `walk_31.png`：连续步态帧，含服务员端盘；当前为引擎实际分件绘制输出。
- `runtime_scene.png`、`runtime_render.json`：隔离存档的正式入口实渲染。90 帧观测中处理时间平均约 6.95 ms、最高约 9.17 ms；仅代表本机该场景的观测，不作为所有硬件的性能保证。

模型、输入与渲染测试使用隔离存档及独立运行锁端口，不覆盖玩家进度。正式游戏通过正常退出流程保存，再启动新版；实窗确认离岗调酒员已回到吧台、所有角色同一地面线，金币继续增长，Godot 编辑器保持运行。重启后游戏 PID 为 41808，日志无 SCRIPT ERROR / ERROR。

未声称完成新的全套 Windows 多屏热插拔、独占全屏覆盖或焦点切换矩阵；这些仍以原桌面验收记录为准。本轮拖动操作由真实视口输入集成验证，正式玩家窗口仅做保存、重启和观察，没有替用户改动布局。
