# CatBar 调酒玩法开发指南

## 当前范围

CatBar 是 960×540、60 physics tick 的 2D 轻俯视像素酒吧。大厅现采用原创暖暗像素背景，形成后墙酒架、中央吧台、七个吧椅和前景三组卡座的层次；程序化热点、调酒师、打工猫与顾客仍位于独立表现层。已完成全景/近景镜头、可按钮或 `Esc` 退出的配置驱动工作台、量取/加液/投冰/撒料/拖勺入杯搅拌/封盖/Shake/倒杯、调酒师与打工猫接力送达、一次性经营结算、卡座氛围循环，以及统一像素主题的手机和微信。

首批可制作配方为“月夜猫语”：月光金酒 30 ml、暮色甜酒 30 ml、透明冰块 2 块、猫薄荷香料 1 份，完成搅拌、封盖、Shake 后倒入蝶形杯。CatBar 杯体按物理帧读取与 Shake 实验相同的粒子/冰块局部只读快照，所以液体会随拖拽惯性晃动并在松手后衰减回稳；剂量和品质仍由领域命令日志决定，不随粒子档位变化。

## 目录边界

- `features/cat_bar/bartending/`：内容 Resource、领域状态、策略、流体适配和工作台。
- `features/cat_bar/camera/`：场景模式和 Camera2D 预设。
- `features/cat_bar/service/`：送达与经营闭环。
- `features/cat_bar/patrons/`：不产生订单的氛围顾客。
- `features/phone/`：手机壳与微信领域/UI。
- `assets/cat_bar/`：可导入运行时资产；`art_source/cat_bar/` 只存美术源文件并由 `.gdignore` 隔离。

跨模块只传稳定 ID、命令、结果和可序列化快照。不得把 Node、Texture 或 Resource 实例写入存档，也不得让 CatBar 反向修改流体求解器内部数组。

## 新增调酒内容

新增器具或原料时，先实现/复用通用交互策略，再创建内容 `.tres` 并放入 catalog 和工作台槽位。新增交互应通过 `InteractionExecutorRegistry` 注册策略，不把业务判断写在 Button 回调。新增配方只引用稳定内容/交互 ID，并为剂量、容差、顺序、杯型和品质阈值配置步骤。

任何新运行时图片都必须加入 `asset_manifest.json`。像素纹理关闭过滤与 mipmap，尺寸必须是单帧整数倍，锚点必须落在单帧内；最终替换占位图时保持资产 ID 不变。本轮生成大厅、两款酒瓶、长柄勺和 2×2 统一猫角色图集均登记为 `PROJECT_GENERATED_REVIEW_REQUIRED`，可用于开发验证，发布前仍需人工美术与授权复核。角色图集四格顺序固定为调酒师、打工猫、夜猫客、下班猫，场景/顾客 Resource 通过纹理区域配置选择角色，业务控制器不硬编码图片路径。

## 微信内容编写

联系人定义包含稳定 ID、显示名、头像 ID、关系标签、解锁事件、简介、兴趣、爱好、人格特征、回复风格、口头禅和四类回复语料。联系人页双击条目进入会话；玩家发送非空文本后，离线回复生成器会按问候、提问、兴趣关键词或普通对话分类并立即回复。回复只依赖联系人配置与独立消息序列，不在 UI 中硬编码角色 ID。

消息/朋友圈模板配置作者集合、触发标签、权重、冷却与互斥键。新存档会确定性预生成五条初始朋友圈；生成后把作者、文案、图片、类别和时间写成实例，所以调整模板不会改写旧历史。玩家消息、好友秒回和已读变化会随微信状态触发正常存档。

订单送达、新一天或认识顾客通过唯一事件 ID 提交。UI 不自行生成内容；消息已读会同步总角标。消息、朋友圈和已处理事件都有容量上限。

## 存档与兼容

`SaveService` v2 保留 v1 的经济和窗口字段，新增 `bartending`、`wechat`、`content_unlocks` 分区。v1 自动补默认分区；未知稳定 ID 被过滤，废弃 ID 可通过映射迁移，单个损坏分区只回退自身。

## 手工测试步骤

1. 在 Godot 4.7.1 中打开项目，直接运行 `features/cat_bar/cat_bar.tscn`；确认大厅能看到暖木酒架、中央长吧台、七个吧椅、三个前景卡座、左侧霓虹猫标与右侧唱片机，且画面没有参考图中的品牌文字。
2. 把鼠标移到吧台中央“点击进入调酒台”区域；确认悬停边框变亮，点击后镜头进入调酒模式，大厅仍作为背景且手机固定在右下角。
3. 在未完成成品时点击“返回大厅”，确认镜头恢复全景；重新进入后杯内没有旧配料。再进入一次并在 Shake 中按 `Esc`，确认同样返回且鼠标不再被捕获。
4. 确认“月光金酒”和“暮色甜酒”显示不同瓶型，“长柄勺”显示猫爪尾饰勺。点击酒瓶应加入对应酒液，不能串酒液 ID。
5. 先往 Shake 杯加入任意酒液并封盖，开始 Shake 后左右/上下往复拖动；确认杯体移动时可见液体粒子和冰块相对杯体晃动，而不是整块静态色条。松手后杯体回到原位，液体继续短暂衰减并保持在杯内。
6. 按配方完成倒酒；确认调酒近景自动收起并返回大厅构图，调酒师先把成品摆在吧台交接点，打工猫随后拿走酒杯并移动到目标卡座。金币、服务数与研发材料只能在卡座放杯后结算一次。
7. 在大厅同时观察调酒师、绿色围裙打工猫、紫色夜猫客和蓝灰下班猫；确认四者头身比例、像素颗粒、轮廓和暖色受光一致，同时服装与托盘能区分职责。
8. 点击右下角 `CAT PHONE`，确认手机主页使用深色机身、暖金边框；微信为绿色可用入口，打车/小红书/拍照显示“即将开放”但点击会给出提示。
9. 打开微信并切换消息、联系人、朋友圈；确认页签高亮、卡片可滚动、朋友圈至少有三条且至少两种类别。关闭再打开手机，内容顺序不能变化。
10. 在联系人页双击店长猫、打工猫或酒吧常客名菜；应自动切到消息页对应会话。输入“你好”“怎么调经典鸡尾酒？”或联系人兴趣词并发送，应立即出现绿色“我”气泡和联系人回复；只输入空格不能发送。
11. 分别和三个联系人聊天，观察店长猫简洁克制、打工猫活泼吐槽、名菜温柔有画面感的差异。完成一次正常存档/重启后，聊天方向、顺序和朋友圈应恢复。

## 自动验证命令

在仓库根目录以 Godot 4.7.1 console 执行对应测试脚本。自动门禁包括粒子流体、Shake Lab、CatBar/微信、资产校验、性能和稳定性。GPU 截图脚本除手机页面外，还会输出 `.work/cat_bar_overview.png`、`.work/cat_bar_mixing.png`、`.work/cat_bar_shake.png`、`.work/cat_bar_shake_reverse.png`、`.work/cat_bar_service_handoff.png` 和 `.work/cat_bar_worker_delivery.png`，可并排检查流体位移与服务阶段。

已知环境提示：Windows 沙箱中可能无法读取根证书或写入 `user://`，生产桌面运行不受该测试沙箱限制。生成式美术目前是开发期素材；音效、四类猫的完整逐帧动画和全量酒具仍需后续替换。
