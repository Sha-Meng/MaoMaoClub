## 1. 依据与范围

- 用户确认：店长自由游走，可与顾客闲聊；店铺、桌椅和角色均可拖动，支持轻量 UGC。
- 比例基准：`design/art/desktop_tavern_v2/desktop_idle_selected_v2.png`。本规划不重新缩放场景或改变用户选择。
- 店长造型：`design/art/desktop_tavern_v2/manager_proportions_v2.png`。
- 首批顾客来自 `validate-mixology-mvp`：汗衫松鼠、领带狗、格衫水豚。狐狸、兔子、浣熊是本轮概念扩展候选。
- 当前代码中所有猫共用 `CatActor`，顾客是移动占位形状；尚无完整的坐姿、调酒、端盘、闲聊动画。以下是目标需求，不能把现有逻辑状态当作动画已完成。
- 建议沿用三猫规模：店长 1 位、调酒员 1 位、服务员 1 位。员工岗位拆分需用户确认后再实现。
- 尚无正式 Art Bible；本轮不锁定单格像素、帧数、骨骼插件、贴图图集尺寸或量产预算。

## 2. 角色职责

| 角色 | 主要行为 | 主动画节奏 | 首批数量 |
| --- | --- | --- | --- |
| 顾客 | 到店、等位、入座、消费、聊天、离开 | 走动 → 安静坐姿 → 偶发喝酒 / 闲聊 | 3 种外观；可有多个实例 |
| 调酒店员 | 在吧台制作与摆出饮品 | 安静工作待机 → 调酒 → 倒酒 → 出杯 | 1 只猫，岗位建议 |
| 服务店员 | 取饮品、送达顾客、收空杯 | 待机 → 持盘行走 → 递杯 → 收杯 | 1 只猫，岗位建议 |
| 店长 | 自由游走、与顾客闲聊、回应玩家 | 待机 / 游走 → 倾听 / 说话 → 继续游走 | 1 只猫 |

P0：首版动作覆盖，先保证闭环和交互可读。P1：形象确定后补充的生活感。P2：后续特色内容。P0 不表示每项都要新画一套逐帧，静态姿势、面部部件和位移/回弹可以复用。

## 3. 顾客动画

### P0：每种首批顾客覆盖 9 项

| 动作 ID | 动作 | 形式 | 触发与结束 | 制作要点 |
| --- | --- | --- | --- | --- |
| `idle_stand` | 站立 / 等位 | 低幅循环 | 无座位或等待下一步 → 行走 / 入座 | 等位与普通站立先共用，点单气泡另层 |
| `walk` | 走路 | 循环 | 入场、找座、离场、重新落位 → 到目标 | 入店/离店复用；位移由逻辑驱动，不在动作里烘焙 |
| `sit_down` | 坐下 | 一次 | 座位有效且预占成功 → `idle_sit` | 臀部对齐座面，杯子不可穿过桌面 |
| `idle_sit` | 坐姿待机 | 低幅循环 | 入座、喝酒或聊天结束 → 下一动作 | 保留原稿的安静座椅待机；呼吸、眨眼幅度小 |
| `drink` | 端杯喝一口 | 一次，可低频重播 | 饮品已送达且当前可喝 → `idle_sit` | 拿起、抿一口、放回，杯子与手准确接触 |
| `chat` | 与店长 / 邻座闲聊 | 短循环 | 对话事件生效 → `idle_sit` / `idle_stand` | 轻嘴型、头/手势；气泡单独显示，不长时间常驻 |
| `stand_up` | 起身 | 一次 | 离店或脱离原座位 → 站立 / 行走 | 与座位绑定状态协调，不能先释放座位却还坐着 |
| `drag_hold` | 被拖动姿态 | 保持姿势或短循环 | 玩家开始拖动 → 释放 | 暂停原动作，收拢腿部；不能拖着固定椅子坐姿悬空 |
| `land` | 放下 / 站稳 | 一次，可用变换反馈 | 释放到有效位置 → 站立 / 重新找座 | 短促站稳，之后遵守新位置；不自动弹回旧的 home 坐标 |

### P1 / P2：顾客增强

| 优先级 | 动作 | 说明 |
| --- | --- | --- |
| P1 | 点单 / 招手 | 与订单气泡配合，先用一个小手势 |
| P1 | 接过酒杯 | 店员送达与顾客收手需要同步接触点 |
| P1 | 付款 / 感谢 | 不依赖“动作播放结束”作为唯一结算依据 |
| P1 | 站姿/坐姿倾听 | P0 可用相应 idle + 转头，后续再独立细化 |
| P1 | 三位首批个性待机 | 松鼠甩尾；狗松领带；水豚慢眨眼 |
| P2 | 三位扩展个性待机 | 狐狸围巾/尾尖；兔子画本；浣熊手机 |
| P2 | 满意、久等、不满、醉态 | 只有相应规则确定后才制作，不提前加入惩罚或醉酒数值 |

首批三个物种的动作逻辑一致，体型、尾巴和服装不同。可以共享动画模板或分件方案，但不能未经适配直接套用同一身体变形。

第二轮人物适配：阿栗采用轻快步频、前倾与较大讲述手势；阿领采用瘦高体态、肩内收及互动后放松；慢慢采用稳定低重心、小幅转头与停顿点头。基础消费流程共用，是否主动发起聊天及回应方式按性格区分；完整触发与退出条件见人物设定。狐狸、兔子和浣熊若进入制作，从 P0 起也需保留各自体型与常态表情，不沿用统一笑脸。

## 4. 店员动画

### 两类店员共同覆盖的 P0：4 项

| 动作 ID | 动作 | 形式 | 触发与结束 | 制作要点 |
| --- | --- | --- | --- | --- |
| `idle_work` | 工作待机 | 低幅循环 | 无任务 → 工作 / 行走 | 吧台猫可只露上半身，但需另有完整身体以支持拖动 |
| `walk` | 空手行走 / 返回 | 循环 | 重新落位或空手移动 → 到目标 | 与端盘走路分开，不能只给走路动作贴一个漂浮托盘 |
| `drag_hold` | 被拖动姿态 | 保持 | 拖动开始 → 释放 | 持有任务时道具跟随或安全收起，订单不得重复分配 |
| `land` | 放下 / 站稳 | 一次，可用变换反馈 | 释放 → 有效工作位置 / 待机 | 保留玩家摆放意图，工作接触点需重新计算 |

### 调酒店员 P0：额外 3 项

| 动作 ID | 动作 | 形式 | 触发与结束 | 道具/挂点 |
| --- | --- | --- | --- | --- |
| `mix_drink` | 摇杯 / 调制 | 短循环 | 订单进入制作阶段 → 制作阶段结束 | 双手、摇酒壶；可先用一套通用调制循环 |
| `pour_drink` | 倒入杯中 | 一次 | 需要出杯 → 杯中准备好 | 瓶或壶、杯子、短暂液体；杯放在吧台挂点 |
| `place_drink` | 放杯 / 推出成品 | 一次 | 饮品可取 → 交给服务员 | 手与杯、吧台取餐点；完成事件只代表成品可取 |

### 服务店员 P0：额外 3 项

| 动作 ID | 动作 | 形式 | 触发与结束 | 道具/挂点 |
| --- | --- | --- | --- | --- |
| `carry_tray` | 持盘行走 | 循环 | 携成品/空杯移动 → 到目标 | 托盘、杯子跟随手部；盘面尽量稳定 |
| `serve_drink` | 递杯 / 放到桌上 | 一次 | 到正确顾客的服务点 → 递送完成 | 明确手 → 桌面/顾客手的接触时刻 |
| `collect_glass` | 收空杯 | 一次 | 顾客饮用结束或离开 → 收取完成 | 桌面杯与托盘杯切换，不能出现两只重复杯 |

### 店员 P1 / P2

- P1：拿瓶、接单、取托盘、擦杯、擦吧台、擦桌子、点击回应、简短闲聊。优先拆分有明显可见收益的动作。
- P2：不同配方专属手法、花式调酒、端盘小失误、伸懒腰、员工互相打招呼。没有对应规则或可读空间时不先做。
- 店员素材可以有上半身工作版本，但拖出吧台时必须切换到完整角色；不能把“只有半截身体”的吧台图直接拖到桌面。

第二轮人物适配：调酒员瘦高、专注且讲究，在 `place_drink` 首尾加入对齐杯子和短暂满意；服务员紧凑活泼，在 `serve_drink` 中由开朗转为专注、轻放杯子再微笑。两项先作为既有动作表演，不因性格新增无休止返工或洒杯惩罚。

## 5. 店长动画

### P0：覆盖 7 项

| 动作 ID | 动作 | 形式 | 触发与结束 | 制作要点 |
| --- | --- | --- | --- | --- |
| `idle` | 自然站立 | 低幅循环 | 停留或对话结束 → 下一行为 | 轻呼吸、尾巴轻动；保持 V2 自然圆润比例 |
| `walk` | 自由游走 | 循环 | 选择游走/社交目标 → 到达 | 金链、背心、尾巴随步态轻动；持杯行走不剧烈甩杯 |
| `chat` | 说话 | 短循环 | 与顾客建立对话 → 自己说话阶段结束 | 朝向对方，轻嘴型、小手势；不持续蹦跳 |
| `listen` | 倾听 / 点头 | 低幅循环 | 顾客说话阶段 → 回复或结束 | 与 chat 交替，避免双方一直同时说话 |
| `react_click` | 玩家点击反馈 | 一次 | 识别为单击 → 回原行为 | 眯眼回应、小举杯或点头，拖动结束不误触发 |
| `drag_hold` | 被拖动姿态 | 保持或短循环 | 拖动开始 → 释放 | 暂停游走与闲聊；酒杯随手一起移动 |
| `land` | 放下 / 站稳 | 一次，可用变换反馈 | 放置有效 → 待机 / 新的游走目标 | 以新位置继续活动，不强制回旧站位 |

### P1 / P2

- P1：招呼进店顾客、单独举杯致意、低频大笑、整理背心/项链、坐下休息（如确认店长也能入座）。
- P2：与熟客的特殊寒暄、专属情绪、偶尔帮忙服务。店长参与订单不属于当前已确认方向，不能为此先要求一整套调酒动作。

第二轮人物适配：店长性格为热情、松弛、有分寸；根据顾客回应调整手势和说话/倾听时长。沉默、画画或看手机的顾客可以不参与；一次招呼未获回应后自然结束并继续游走，不持续追逐或反复打断。同一店长的常态半睁眼、认真倾听与眯眼笑应区分为情境表情。

## 6. 首版动作数量与复用

| 范围 | P0 定义条目 | 说明 |
| --- | --- | --- |
| 顾客模板 | 9 | 三位首批顾客各覆盖相同九项 |
| 店员共用模板 | 4 | 调酒员和服务员各覆盖四项 |
| 调酒员专用 | 3 | 调制、倒酒、出杯 |
| 服务员专用 | 3 | 持盘行走、递杯、收杯 |
| 店长 | 7 | 待机、游走、说话、倾听、点击、拖动、放下 |
| 合计 | 26 | 按角色模板整理的动作定义数量 |

若每个角色都独立覆盖：三顾客 27 项 + 调酒员 7 项 + 服务员 7 项 + 店长 7 项 = 48 项角色动作覆盖。新增三位顾客再增加 27 项覆盖。上述不是必须新画的独立动画套数，也不是图像帧数：idle、drag_hold、land 可部分由静态姿势、面部切换和变换反馈完成。

建议制作顺序：

1. 先只拿领带狗、店长和两位店员做动作样例：走路、入座、坐姿、喝酒、聊天、调制、递杯与拖动/释放。
2. 在用户选定的实际屏幕比例下检查轮廓、手杯接触和动作可读性，再确定帧数与播放节奏。
3. 覆盖完整 P0，并将顾客模板适配到松鼠和水豚。
4. 补首批个性 P1，最后决定是否量产三个扩展角色。

## 7. 朝向、分层与锚点

- 首版优先横向左右行走 + 对话三分之四朝向，不先制作八方向全套。左右镜像需检查领带、围巾、尾巴、握杯手和文字，不可盲目翻转可读标记。
- 站姿统一脚底基准；坐姿统一臀部挂点对齐座面；各帧画布/裁切原点一致，防止角色上下抖动。
- 酒杯、饮品液体、托盘、摇酒壶、瓶子、手机、画本、工作包与角色尽量拆层；角色本体不永久绑死在某个道具姿势。
- 椅子、桌子、吧台是可摆放场景对象，不烘焙进角色逐帧素材；坐姿遮挡与前后关系需由场景排序处理。
- 台内工作显示与台外完整身体的切换保持角色体型一致；拖动之后不能突然换成不同大小的猫。
- 在小尺寸下优先让走路、坐下、喝酒、递杯和聊天朝向可辨认；微表情和衣物细节随后加。
- 以安静自然的少帧动作或分件动画验证即可，本轮不预先绑定第三方插件、骨骼格式或最终 FPS。

## 8. 自由摆放下的中断与恢复建议

| 场景 | 表现方案 | 逻辑约束 |
| --- | --- | --- |
| 拖动坐着的顾客 | 切为被拖动姿态，杯子随手/安全收起；松手站稳再选择后续姿态 | 原座位占用解除或转移；不能同时占两个座位 |
| 拖动有顾客的椅子 | 建议顾客与座面挂点一起移动，避免椅子走了人留空中 | 人椅关系及有效摆放范围需用户确认 |
| 拖动店铺 | 店铺内员工与吧台工作挂点整体跟随 | 外部送餐目标、取餐点与路径需更新 |
| 拖动调酒员 | 暂停/安全结束当前手部动作；放下后从有效阶段继续 | 订单保留唯一身份，不能再分配第二笔重叠服务 |
| 拖动持盘店员 | 切持盘拖动姿势或安全收道具，释放后继续任务 | 饮品不丢失、不复制；动画不能直接重复发奖 |
| 拖动店长 | 结束当前闲聊轮次并转为拖动/落地 | 顾客解除社交锁定，双方可以恢复自己的待机 |
| 接触对象被移动/删除 | 终止坐下、喝酒或递杯接触动作并安全回到待机 | 动画事件使用稳定对象身份，不仅依赖旧坐标 |

顾客拖动、占用椅子的移动、空中放置及任务栏吸附规则仍待细化；本表是避免动作与自由摆放冲突的建议，不是暗中限制全物件可拖动。

## 9. 与现有实现的差距

- `features/customers/customer_state.gd` 当前只有进店、请求、等待、服务中、付款、离开；没有坐姿、饮用、聊天或拖动状态。
- `features/cats/cat_state.gd` 当前统一管理猫猫状态，没有店长、调酒员、服务员职责区分。
- 当前 `CatActor` 释放后朝固定 home 返回；未来需兼容玩家重新摆放的位置，不能把新的布局复原成旧布局。
