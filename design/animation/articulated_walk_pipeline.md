# 关节驱动步态

> 当前运行实现记录。用户已反馈关节视觉不自然，本方案未完成视觉验收；后续制作建议见 `authored_animation_research.md`。

日期：2026-10-17。固定 Godot 4.6.3 stable。替代用户指出不自然的脚底平移方案。

## 原因

旧方案有稳定脚底和正确遮挡，但把腿当成被脚拖动的连续布片，没有真正的膝、踝配合。原站姿两脚横向分得较开，各自围绕原位置运动还会造成一脚迈得窄、下一脚迈得宽。头部永远固定、脚掌永远不转也不是正常行走标准。

本轮参考接触、下沉、经过、抬起四个关键姿态，按角色比例做克制的步态。参考：[Animation Mentor 官方步行教程](https://www.animationmentor.com/blog/tutorial-animating-human-walk-cycle/)。

## 实现

- 原人物纹理 `assets/tavern/grounded/` 保留；没有重画身份、混合独立姿势或恢复旧分件贴图。
- `TavernWalkPose.JOINTS` 记录每种体型的髋、膝、踝。两段 IK 保持原骨段长度，膝盖朝行走方向弯曲；连续网格围绕关节转动，脚掌刚性旋转，不单独缩放肢体。
- 支撑占周期 60%、摆动占 40%，两脚有短暂同时支撑。足部水平轨迹与实际位移匹配，承重中段平放，摆动时屈膝、提脚和转踝。
- 步幅按腿长限制，避免短腿为了够到落点而深蹲和折叠。移动速度同步减小，维持每秒约 1.7～1.9 步；宽脚掌的转踝角度受离地高度约束，避免脚尖或脚跟穿地。兔子切分线落在实际两脚之间。
- 髋部投影在行走时靠近身体中轴，双脚落脚轴只保留 3 个逻辑像素的近远投影差。初次起步各脚仅在自己的第一次摆动期调整到行走轴；支撑时不调整，停止也不重置。
- `walk_cycles` 记录本次实例已行走的累计周期，仅用于起步对齐；不会驱动营业或写入旧存档格式。`walk_phase` 仍按实际水平位移推进。
- 触地后身体承重下沉，经过时回升；骨长可达约束用平滑包络衔接，避免两腿交接时产生速度折角。躯干与头部整体平移，原画形状不变。
- 空手绕肩与同侧腿反向摆动。手在髋旁的像素优先属于手臂，避免被腿部权重带走；店长持杯手、服务员托盘与躯干同动。
- 原稿左腿为近腿，仍先画远腿再画近腿，左右镜像不换层。局部重心、脚踝运动不改变世界 Y=270、无纵深的交互规则。

## 验证

`./tools/run_tests.ps1 -Render` 包含骨长、足部刚性、至少一脚支撑、摆动膝与支撑膝差异、接触后下沉、手脚对摆、行走轴及起步对齐测试，另保留营业、坐姿、饮用和存档回归。

GPU 像素检查在承重中段量取脚底；头部先消除有意的重心平移，再比较像素。双腿遮挡只检查真实 alpha 且颜色标记明确的内部像素，原图切分边缘的双线性混色不算纯色标记。原色 alpha 连通检查继续独立执行。

`render_articulated_keys.gd` 输出四阶段原色与关节图；`render_smooth_walk.gd` 输出原尺寸/两倍、浅深底的真实 30 FPS 行走、停步、反向帧。编码：

```text
python tools/encode_grounded_walk_review.py production/qa/articulated_walk
```

最新验证记录：`production/qa/articulated_walk/acceptance.md`。原色正常速度复看是必要环节，数值正确不等于用户已认可动作自然度。
