# 成熟角色动画方案调研

日期：2026-10-17。最终选择：用户要求免费且由代理完成，已执行 Blender 分层骨骼 → 透明动画图集 → Godot 4.6.3 的单店长验证。详情见 `manager_blender_pilot.md`；全员与正式营业入口尚未迁移，用户视觉验收待确认。

## 用户参考与当前问题

用户参考：[普通路过kiki《请看做了很久的Live2D走路动画》](https://www.bilibili.com/video/BV1P5JXzpEhn/)，页面发布日期 2025-09-24。已打开视频页面，观察开头正面步行对比；没有取得作者的分层原稿或模型，不能据此断言其具体绑定参数，也不复制视频素材。

当前关节版被用户明确反馈“关节太奇怪”。上一轮 54 用例及渲染检查通过，只能说明相应数值和业务检查通过，视觉步态未验收。

代码事实与诊断：

- `tavern_grounded_gait.gd` 把完整站姿纹理沿固定 X 切成两侧，并用坐标范围计算权重。
- `tavern_walk_pose.gd` 在预设高度带内改变旋转中心和旋转角度。骨段长度成立，不保证腿的轮廓、裤子纹理、胯部和关节弯曲形状成立。
- 在完整人物图上变形，无法补出腿后、胯后、袖口和被手挡住的身体。近远腿投影靠拢还会压扭原站姿的宽度关系。
- 调研开始时工程 `assets/`、`design/` 未找到 PSD、KRA、ORA、Spine、Cubism 模型源文件。现已新增店长 `.blend` 源工程；旧 PNG 分件不等于已完成补画、绑定与关键姿态的动画原稿。

结论：需要换成正式动画素材制作流程。IK 可以保留为制作工具；主要缺口是原画分层、网格拓扑、权重、关键姿态和运动曲线。

## 成熟方案比较

| 路线 | 已核实能力 | 对本项目的判断 |
| --- | --- | --- |
| Live2D Cubism | 网格、旋转变形器、曲面变形器、关键形状、动画时间线；支持 PNG 序列导出 | 最贴近用户参考的插画表现方式；需要逐角色精细分层和形变制作。适合强调表情、身体转向、柔软衣物的表现 |
| Spine Professional | 骨骼、网格权重、IK、变形关键帧；官方提供 Godot 运行时和 PNG 序列/图集导出 | 推荐用于本项目的全身行走、坐下、递杯、持盘和多角色动作生产。属于项目适配判断，不是工具自动保证质量 |
| Godot 原生分层动画 | 4.6 文档包含 Skeleton2D、Bone2D、Polygon2D 权重及内部顶点，AnimationPlayer 可制作动画 | 不增加外部动画编辑器采购，能实现标准制作方式；仍须完成分层补画和逐姿态调整，不能直接把现有整图套进去期待改善 |
| Blender 分层骨骼 | 免费、原生骨骼权重、关键帧、Python 自动化和透明渲染 | 用户最终选择；店长已完成可编辑源工程与 Godot 独立样片，最终美术效果仍待确认 |
| 手绘或工具烘焙的序列帧 | Godot 4.6 的 AnimatedSprite2D / SpriteFrames 可播放 | 适合作为首个样片和当前固定角色的交付格式；动作与换装组合增加时，贴图数量和显存成本也增加 |

Spine 的网格功能不包含在 Essential 中，正式制作需考虑 Professional 的授权。Live2D 官网列出的官方 SDK 平台没有 Godot；实时接入需额外评估集成方案。Spine 官方有 GDExtension 和自定义引擎模块两条接入路径，但本轮未验证某个二进制在项目精确构建 4.6.3 上的兼容性。

## 最终采用的制作与交付方式

用户选择 **完整分层素材 → Blender 4.5.9 LTS 骨骼与关键帧 → 透明序列帧/图集 → Godot 4.6.3 播放**。Blender 仅作为离线制作工具；不依赖 Spine 授权，不增加游戏内第三方动画运行时。交付 `.blend`、原稿与提示词、构建脚本、图集、动作元数据、独立预览和测试证据。

先验证店长，后续是否扩展由样片效果决定。独立验证的功能与限制见 `manager_blender_pilot.md`。

## 较早的原生方案建议（历史记录）

较早针对“可以直接落地”提出过 **重新制作完整分层素材 → Godot 4.6.3 原生分层绑定 → AnimationPlayer 制作关键帧 → 局部替换帧校正轮廓 → 原生运行**；该建议已由上述免费 Blender 方案取代。

使用 Sprite2D 分层、Skeleton2D / Bone2D 组织绑定、AnimationPlayer 驱动明确制作的姿态与曲线。骨骼负责连接和姿势；膝部、脚掌、握杯手在需要时切换专门绘制的局部姿势。身体、衣摆等只做受控的局部变形，不能继续把整张站姿按高度带扭成走路动作。

此路线可以使用现有固定引擎完成编辑、预览和运行。本机已安装程序记录未找到 Spine / Cubism，未确认这些软件的授权；此前 Spine 建议针对专业制作管线，本轮把立即实施的工具依赖收敛到现有 Godot。素材分层、遮挡补画和关键姿态仍是必要制作工作。

可在制作完成后按需烘焙为透明序列，或保留原生分层场景运行。后续引入专业美术生产时，Spine 制作及官方 Godot 运行时仍是备选，需单独确认工具授权和版本兼容性。

目前轻量 UGC 主要是人物和家具摆放，制作好的动作片段不会妨碍横向拖动、营业或社交状态切换；移动、座位、订单和存档仍由现有逻辑负责。不能通过烘焙现有错误网格获得正确步态。

## 首个角色：店长

1. 保持用户选定比例、体型、表情和画风，制作适合横向移动的三分之四视角原稿。视频里的正面行走主要用于表现质量参考，不能原样套成横向步态。
2. 分层至少包含头、耳、表情、胸腹、骨盆/衣摆、近远上臂/前臂/手、近远大腿/小腿/脚、尾巴、杯子。补全遮挡区域，肩、胯、膝、踝保留可控的重叠和弯曲空间。
3. 建立接触、承重、经过、抬起及对侧对应姿势，人工调整轮廓和曲线。短腿店长使用小步幅，腹部和衣摆保持体积；脚掌要有落地与离地关系。尾巴、衣摆、头部可以有轻微延迟，不能整身同频振动。
4. 先交付待机、起步、持续行走、停步和持杯行走。杯子绑定手部挂点；持杯侧不用普通空手摆臂轨迹。
5. 样片按正式常驻尺寸、两倍检查尺寸、浅深背景，输出左右方向与连续走停。确认样片效果后，再覆盖其他体型及坐下、饮用等动作。

每个片段交付：可编辑源文件、透明序列/图集、固定画布与根锚点、时长、循环区间、步幅、接触相位、道具挂点或烘焙持物变体、事件标记。不同体型分别校正绑定和动作。

## 验收变更

- 自动验证保留状态切换、相位连续、资源完整性、事件只触发一次、营业与存档。
- 不再把“始终同一站姿图”“精确 60% 支撑期”“固定重心曲线”当作最终艺术约束。
- 必须检查正常速度下的完整轮廓：肩/胯接续、膝踝弯曲、脚掌厚度、遮挡、杯手连接、起停和循环接缝。
- 运行流畅与姿态自然分别报告。功能测试通过不能替代用户对动作效果的认可。
