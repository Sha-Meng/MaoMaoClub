## Requirements
### Requirement: 手机壳层与应用入口

系统 MUST 在普通场景下于屏幕右下角显示手机入口，点击后 MUST 打开独立于世界相机的手机页面；手机壳 MUST 提供应用入口、返回栈、关闭操作和未读角标，并 MUST 预留未实现应用的禁用槽位。

#### Scenario: 从全景打开手机

- **WHEN** CatBar 处于允许打开手机的全景模式且玩家点击手机
- **THEN** 手机页面显示在世界画面之上并获得唯一 UI 输入焦点
- **AND** 世界相机位置不因手机打开而改变

#### Scenario: 点击未实现应用

- **WHEN** 玩家点击打车、小红书或拍照等未实现入口
- **THEN** 系统显示明确的未开放状态或禁用反馈
- **AND** 不创建空白页面或破坏手机返回栈

### Requirement: 微信三页签

微信 MUST 提供消息、联系人和朋友圈三个可切换页签，并 MUST 在切换时保留当前会话内的滚动/选择状态；页面展示 MUST 只消费微信领域状态的只读视图模型。

#### Scenario: 切换微信页签

- **WHEN** 玩家依次切换消息、联系人和朋友圈
- **THEN** 每个页签显示对应的数据集合与空状态
- **AND** 切换页签不会重新随机生成消息或朋友圈

#### Scenario: 从微信返回

- **WHEN** 玩家在微信首页执行返回
- **THEN** 手机回到应用入口页
- **AND** 再次打开微信时已生成内容仍然存在

### Requirement: 初始联系人

新存档 MUST 默认解锁店长猫、打工猫、酒吧常客名菜三个稳定联系人；联系人定义 MUST 至少包含稳定 ID、显示名、头像资源 ID、关系标签和解锁条件。

#### Scenario: 首次打开联系人页

- **WHEN** 玩家使用新存档首次打开微信联系人
- **THEN** 页面显示店长猫、打工猫和酒吧常客名菜且不重复
- **AND** 每个联系人显示配置的姓名与头像或合法占位头像

#### Scenario: 解锁新朋友

- **WHEN** 外围系统提交带唯一事件 ID 的合法联系人解锁事件
- **THEN** 微信新增对应联系人并可在后续生成内容中选为作者
- **AND** 重复提交同一事件不会产生重复联系人

### Requirement: 消息列表与随机消息

消息页 MUST 按最近活动时间展示已解锁联系人的会话摘要、最新消息和未读数；随机消息 MUST 从满足作者、解锁条件、标签、冷却和互斥规则的模板生成。

#### Scenario: 生成一条好友消息

- **WHEN** 合法触发事件到达且存在可用消息模板
- **THEN** 生成器选择已解锁好友与合格模板并创建一次消息实例
- **AND** 对应会话移动到列表前部且未读数增加

#### Scenario: 打开有未读消息的会话

- **WHEN** 玩家打开一个包含未读消息的好友会话
- **THEN** 页面按时间顺序显示已有消息实例
- **AND** 该会话未读数清零且总角标同步更新

#### Scenario: 没有合格模板

- **WHEN** 触发事件发生但全部模板处于冷却、互斥或解锁条件不满足
- **THEN** 本次生成安全跳过并留下可诊断原因
- **AND** 不创建空文本或引用未解锁作者的消息

### Requirement: 朋友圈内容实例

朋友圈 MUST 展示作者头像、作者名、文案、时间标签、内容类别和零至多张配置图片；首批内容池 MUST 覆盖日常、酒吧打卡、旅游 vlog、人生感悟和职业吐槽五类。

#### Scenario: 生成带照片的酒吧打卡

- **WHEN** 酒吧相关触发事件允许生成朋友圈且存在合格打卡模板
- **THEN** 时间线新增一个包含已解锁作者、打卡文案和合法图片资源 ID 的实例
- **AND** 新实例位于时间线前部且不会因重新打开页面而改变

#### Scenario: 生成纯文字感悟

- **WHEN** 生成器选择允许零张图片的人生感悟模板
- **THEN** 时间线显示头像、文案和时间标签
- **AND** 图片区域不保留破坏布局的空白占位

#### Scenario: 图片资源缺失

- **WHEN** 已保存朋友圈实例引用的图片资源不再存在
- **THEN** 页面使用配置占位图或隐藏该图片槽位
- **AND** 文案、作者和其他时间线实例仍可显示

### Requirement: 确定性生成与历史稳定

微信生成器 MUST 保存基础种子和递增游标，并 MUST 把生成后的作者、文本、图片 ID、类别和时间保存为实例；相同状态与事件序列 MUST 产生相同新增内容，既有历史 MUST 不受模板权重调整影响。

#### Scenario: 相同事件序列重放

- **WHEN** 两个测试状态使用相同联系人、模板版本、种子、游标和触发事件序列
- **THEN** 两者生成相同的消息与朋友圈实例序列
- **AND** 结果不依赖 UI 打开次数或渲染帧率

#### Scenario: 更新模板后加载旧历史

- **WHEN** 配表更新后加载包含旧消息与朋友圈实例的存档
- **THEN** 旧实例继续显示其已保存内容
- **AND** 新模板只影响后续生成内容

### Requirement: 外围事件增量扩展

微信服务 MUST 通过稳定的领域事件接口接收认识朋友、完成调酒订单、进入新一天和其他外围进度，并 MUST 允许事件解锁联系人、生成消息或生成朋友圈而不依赖 CatBar 场景 Node。

#### Scenario: 调酒送达触发社交内容

- **WHEN** 一个带唯一事件 ID 的调酒订单成功送达且满足模板条件
- **THEN** 微信服务按配置解锁或生成对应社交内容
- **AND** 微信 UI 未打开时内容仍写入领域状态并更新未读角标

#### Scenario: 重复外围事件

- **WHEN** 同一个唯一事件 ID 被重复提交
- **THEN** 微信服务忽略已处理事件
- **AND** 联系人、消息和朋友圈均不重复生成

### Requirement: 微信持久化与容量控制

系统 MUST 在 `user://` 版本化存档中保存联系人解锁、消息实例、朋友圈实例、未读状态、生成种子、生成游标和已处理事件摘要；加载 MUST 校验字段与稳定 ID，并 MUST 以配置上限控制历史条目数量。

#### Scenario: 保存并恢复微信状态

- **WHEN** 玩家生成内容、阅读部分消息、保存并重新进入游戏
- **THEN** 联系人、时间线顺序、已读/未读状态和生成游标恢复
- **AND** 重新进入不会自动复制上一条随机内容

#### Scenario: 从旧存档迁移

- **WHEN** 加载不包含微信分区的 v1 存档
- **THEN** 系统保留旧经济与窗口数据并建立默认微信状态
- **AND** 初始联系人正确存在且存档版本升级

#### Scenario: 历史达到上限

- **WHEN** 新内容生成后消息或朋友圈历史超过配置上限
- **THEN** 系统按明确的归档/淘汰策略保留最新有效历史
- **AND** 不遗留与已删除条目对应的 UI 节点或错误未读数

### Requirement: 微信列表可用性

微信页面 MUST 在目标窗口内支持滚动、空状态、长文本换行和图片自适应；列表条目数量 MUST 受数据上限或视图复用约束，非交互装饰 MUST 不拦截按钮输入。

#### Scenario: 展示长文案与多图

- **WHEN** 朋友圈实例包含接近配置上限的文案和多张图片
- **THEN** 文案在卡片内换行且图片保持配置比例
- **AND** 玩家可滚动到下一条内容而不发生控件重叠

### Requirement: 手机与微信像素酒吧美术

手机壳、应用主页和微信页面 MUST 使用与 CatBar 大厅一致的暖暗像素酒吧视觉语言，并 MUST 通过高对比文字、状态颜色和分层面板保持消息、联系人、朋友圈及输入控件可读；视觉装饰 MUST 不拦截交互输入。

#### Scenario: 打开手机主页

- **WHEN** 玩家从 CatBar 全景打开手机
- **THEN** 手机显示深色机身、暖金/木棕边框和带明确状态的应用图标网格
- **AND** 未开放应用与微信入口在颜色和文字上可区分

#### Scenario: 浏览微信动态内容

- **WHEN** 微信展示长消息、联系人资料、聊天气泡或多条朋友圈
- **THEN** 内容使用统一像素面板层级与微信绿强调色且文字对比度足够
- **AND** 装饰背景不会吞掉双击、滚动、输入或发送事件

### Requirement: 联系人人格与回复配置

每个微信联系人定义 MUST 包含稳定 ID、简介、兴趣、爱好、人格特征、回复风格和分类回复语料；领域回复逻辑 MUST 只依赖联系人配置与稳定运行时状态，不得按具体联系人 ID 在 UI 中硬编码文案分支。

#### Scenario: 校验默认联系人资料

- **WHEN** 系统加载默认微信目录
- **THEN** 店长猫、打工猫和酒吧常客名菜均具有非空人格、兴趣与回复风格配置
- **AND** 所有分类回复模板均可生成非空文本

#### Scenario: 新增联系人回复风格

- **WHEN** 开发者添加一个配置完整的新联系人并解锁
- **THEN** 该联系人可以使用自身模板与口头禅回复玩家
- **AND** 不需要修改微信展示层的联系人 ID 分支

### Requirement: 双击联系人进入可发送聊天

联系人页 MUST 支持鼠标双击已解锁联系人进入对应消息会话；会话 MUST 展示玩家与好友的消息方向、提供文本输入与发送操作，并 MUST 在发送有效文本后立即追加一条由联系人配置生成的回复。

#### Scenario: 双击联系人

- **WHEN** 玩家在联系人页双击“店长猫”条目
- **THEN** 微信切换到消息页并打开店长猫的会话
- **AND** 既有未读消息被标记为已读

#### Scenario: 发送消息并秒回

- **WHEN** 玩家在已打开会话输入非空文本并发送
- **THEN** 时间线立即按顺序追加玩家消息与该联系人的回复
- **AND** 回复文本符合联系人配置的兴趣、人格或回复风格语料

#### Scenario: 发送空白文本

- **WHEN** 玩家只输入空白字符并点击发送
- **THEN** 系统不创建玩家消息或联系人回复
- **AND** 输入框保持可继续编辑且会话历史不改变

### Requirement: 聊天历史持久化与序列隔离

系统 MUST 保存玩家消息方向、好友回复及独立消息序列；玩家聊天 MUST 不改变外围事件生成器的确定性游标，旧存档中缺失方向的消息 MUST 迁移为好友消息。

#### Scenario: 保存聊天后重载

- **WHEN** 玩家与联系人聊天、保存并重新进入游戏
- **THEN** 玩家消息和好友秒回以原顺序与方向恢复
- **AND** 下一条外围事件内容与未进行聊天时使用相同事件游标

### Requirement: 新存档初始朋友圈

新微信状态 MUST 从合格模板中确定性生成至少三条初始朋友圈实例；这些实例 MUST 保存作者、文案、类别、图片和时间，恢复存档或重新打开页面不得重复抽取。

#### Scenario: 首次打开朋友圈

- **WHEN** 玩家使用新存档首次进入朋友圈
- **THEN** 时间线展示至少三条来自已解锁好友的随机化初始内容
- **AND** 内容至少覆盖两个不同类别并可包含配置图片

#### Scenario: 重开微信

- **WHEN** 玩家关闭并再次打开微信而没有新的外围事件
- **THEN** 初始朋友圈的数量、顺序和内容保持不变
- **AND** 不追加重复实例
