## Requirements
### Requirement: CatBar 产品场景

系统 MUST 提供名为 `CatBar` 的可独立运行 2D 酒吧场景，并以轻俯视像素风呈现吧台、卡座、Neko 与必要环境层；场景 MUST 在 Godot 4.7.1 stable 下无需依赖主场景即可启动。

#### Scenario: 独立启动 CatBar

- **WHEN** 开发者直接运行 CatBar 场景
- **THEN** 场景显示完整酒吧全景和可识别的调酒台、卡座与 Neko
- **AND** 不因缺少外部场景节点或未初始化存档而报错

#### Scenario: 使用占位素材启动

- **WHEN** 某个最终像素素材尚未交付但配置标记了合法占位资源
- **THEN** CatBar 使用占位资源保持布局和交互可运行
- **AND** 缺失内容会被诊断而不是生成不可点击的空节点

### Requirement: 功能区边界

CatBar MUST 定义调酒台、卡座和外围 UI 的明确边界与稳定区域 ID；世界热点 MUST 只在其所属场景模式可交互，卡座首阶段 MUST 作为持续表现区存在。

#### Scenario: 全景点击调酒台

- **WHEN** 场景处于全景模式且玩家点击启用的调酒台热点
- **THEN** 系统请求进入调酒模式
- **AND** 卡座表现状态不会因进入调酒近景而被重建

#### Scenario: 调酒近景点击卡座

- **WHEN** 场景处于调酒模式且玩家点击近景外的卡座区域
- **THEN** 系统不会触发卡座或第二个调酒会话
- **AND** 当前调酒输入焦点保持有效

### Requirement: 全景与调酒近景镜头

系统 MUST 为全景与调酒近景提供具名相机构图预设，并 MUST 通过有界时长的平滑过渡进入和退出调酒台；过渡期间 MUST 阻止会造成重复状态切换的世界输入。

#### Scenario: 开始调酒时拉近镜头

- **WHEN** 有可开始的调酒会话且玩家进入调酒模式
- **THEN** Camera2D 从全景预设平滑移动并缩放到调酒台预设
- **AND** 过渡完成后隐藏入口按钮，并启用与近景背景对齐的实体器具和原料交互
- **AND** 不显示独立的完整调酒面板或分类菜单

#### Scenario: 调酒结束后恢复全景

- **WHEN** 成品已交付或玩家安全取消未提交的会话
- **THEN** Camera2D 返回全景预设
- **AND** 世界热点在过渡完成后恢复可用

### Requirement: 场景模式与输入所有权

系统 MUST 使用显式场景模式管理全景、镜头过渡、调酒、送酒和手机界面，并 MUST 确保同一时刻只有一个交互层拥有指针拖拽和点击焦点。

#### Scenario: Shake 中请求打开手机

- **WHEN** 玩家正在 Shake 或倒酒且点击手机入口
- **THEN** 系统拒绝打开手机并保持当前拖拽捕获
- **AND** 杯体与调酒会话不会进入半完成状态

#### Scenario: 手机关闭后恢复场景

- **WHEN** 玩家从允许打开手机的场景模式打开并关闭手机
- **THEN** 系统恢复打开前的合法场景模式
- **AND** 关闭手机的点击不会穿透触发世界热点

### Requirement: Neko 送酒表现

系统 MUST 在成品准备完成后先由调酒师 Neko 把酒杯摆到具名吧台交接点，再由打工猫从交接点取杯、前往目标卡座、放杯并返回；两个角色 MUST 是独立演员，交接顺序 MUST 可观察，且订单交付事件 MUST 只在打工猫完成卡座放杯后至多提交一次。

#### Scenario: 正常送达成品

- **WHEN** 调酒会话产生可交付成品并绑定有效卡座
- **THEN** 调酒师从工作位把成品摆到具名吧台交接点
- **AND** 打工猫取杯后沿配置路径前往卡座并在放杯完成时提交一次交付事件

#### Scenario: 送酒动画资源缺失

- **WHEN** 调酒师或打工猫的某个送酒动画缺失但逻辑路径有效
- **THEN** 系统使用统一画风静态姿势与降级移动完成两段式送达
- **AND** 在受控超时内仍只提交一次交付事件

#### Scenario: 正常接力送达成品

- **WHEN** 调酒会话产生可交付成品并绑定有效卡座
- **THEN** 调酒师先把成品摆到吧台交接点并显示中间成品
- **AND** 打工猫随后取走成品并沿配置路径前往目标卡座
- **AND** 卡座放杯完成时系统发出一次包含订单 ID 和成品结果的交付事件

#### Scenario: 交接演员动画资源缺失

- **WHEN** 调酒师或打工猫的某个动作动画缺失但逻辑路径有效
- **THEN** 系统使用统一画风静态姿势与降级移动完成交接和送达
- **AND** 在受控超时内仍只提交一次交付事件

#### Scenario: 重复阶段回调

- **WHEN** 同一 delivery key 重复收到放杯、取杯或最终送达回调
- **THEN** 系统不会启动第二个并行送酒流程
- **AND** 订单奖励与经营进度最多结算一次

### Requirement: 像素画面稳定性

CatBar MUST 使用统一像素基准、整数缩放策略和无过滤的像素纹理配置，使静止和镜头移动时的关键轮廓保持清晰；UI MUST 独立于 Camera2D 缩放。

#### Scenario: 镜头往返检查

- **WHEN** 相机在全景和调酒近景之间往返
- **THEN** 吧台边缘、器具图标和 Neko 轮廓不出现持续亚像素抖动或模糊
- **AND** 手机入口的屏幕位置和尺寸保持不变

### Requirement: 暖暗像素大厅构图

CatBar 大厅 MUST 依据用户参考图的暖木、深色墙面、酒瓶陈列、霓虹猫标和轻俯视卡座层次重新创作原创像素构图；大厅背景 MUST 与交互热点、Neko、顾客和镜头预设分层，且不得直接使用参考图或复制其中品牌文字。

#### Scenario: 查看酒吧全景

- **WHEN** 玩家进入 CatBar 全景模式
- **THEN** 画面可清晰识别后墙酒架、中央长吧台、吧椅与前景卡座
- **AND** 暖色灯光、霓虹强调和深色留白形成与调酒台、手机一致的视觉体系

#### Scenario: 点击大厅功能区

- **WHEN** 玩家把鼠标移动到吧台热点或观察卡座顾客
- **THEN** 程序化交互覆层仍与实际点击/占用区域对齐
- **AND** 背景装饰不拦截热点、Neko 送酒或顾客表现层输入

### Requirement: CatBar 猫角色统一视觉

CatBar 的调酒师、打工猫和代表性卡座顾客 MUST 使用同一原创暖暗像素角色体系，包括一致的轮廓语言、像素密度、光影方向、色板约束与显示比例；角色职责 MUST 通过服装、道具和稳定角色 ID 清晰区分。

#### Scenario: 查看大厅角色

- **WHEN** 玩家在全景中同时看到调酒师、打工猫和卡座顾客
- **THEN** 所有猫角色具有一致的像素边缘、头身比例和暖色环境光
- **AND** 调酒师可由马甲或领结识别、打工猫可由围裙或托盘识别

#### Scenario: 角色图集缺失

- **WHEN** 任一角色纹理无法加载
- **THEN** 对应演员使用可识别的程序化占位表现继续完成逻辑
- **AND** 缺失纹理不会阻止调酒、交接、送达或顾客环境循环
