# 任务

## 规格与设计

- [x] 新增调酒经营 MVP 的 OpenSpec 规格。
- [ ] 明确调酒经营 MVP 依赖桌面挂机基础场景，但独立验收调酒策略闭环。
- [ ] 将实现完成后的稳定行为合并到 `openspec/specs/mixology-experience/spec.md`。

## 数据与规则

- [ ] 定义三类 MVP 顾客：流氓汗衫松鼠、扎领带的狗、格子衫水豚。
- [ ] 定义三种 MVP 材料：松木皮、枸杞、黑胡椒。
- [ ] 定义顾客与材料映射：松鼠掉落松木皮，狗掉落枸杞，水豚掉落黑胡椒。
- [ ] 定义至少五种初始可研发酒水：松木汽泡酒、枸杞热托迪、黑胡椒朗姆、社畜安慰剂、办公楼夜风。
- [ ] 定义每种酒水的材料消耗、偏好顾客和经营效果。

## 材料掉落

- [ ] 实现顾客离开时根据顾客类型计算材料掉落。
- [ ] 实现同类顾客接待次数成长带来的掉落概率提升。
- [ ] 设置掉落概率上限，避免无限成长。
- [ ] 在 UI 中展示材料获得反馈和材料库存。

## 研发与今日菜单

- [ ] 实现调酒研发入口，可以从酒摊或临时 MVP 面板打开。
- [ ] 展示当前材料库存、可研发酒水、缺失材料和研发结果。
- [ ] 实现消耗材料解锁酒水。
- [ ] 实现今日菜单配置，只允许加入已解锁酒水。
- [ ] 限制今日菜单最多 10 种酒水。

## 经营影响

- [ ] 让今日菜单影响至少一种顾客出现权重。
- [ ] 让今日菜单影响至少一种收益结果，例如客单价、停留时间或消费倍率。
- [ ] 提供客群结构、订单收益或营业摘要，方便玩家比较配置变化。
- [ ] 验证“研发酒水 -> 放入今日菜单 -> 后续顾客或收益变化”能被玩家观察到。
