## Context

当前 CatBar 通过 Resource 内容目录驱动调酒台，酒液和器具只有稳定 `asset_id` 与 SVG 占位图；长柄勺按钮只在自身范围累计鼠标移动，缺少明确落点。微信领域层已有确定性模板生成器与 v2 存档，展示层能查看联系人、消息和朋友圈，但消息实例不区分玩家/好友，联系人也没有人格或回复语料。

本轮同时跨越美术资产、调酒输入、微信领域状态、UI 与存档。必须保持 Godot 4.7.1、离线可运行、typed GDScript、稳定内容 ID 和 headless 可测。

## Goals / Non-Goals

**Goals:**

- 让两种现有酒液显示各自原创像素瓶身，长柄勺显示原创像素器具图。
- 让大厅和手机形成统一的暖暗像素酒吧视觉语言，同时不牺牲交互可读性。
- 把长柄勺操作建模为“开始拖拽—进入容器—积累轨迹—容器内释放”的空间手势。
- 用每联系人 Resource 提供完整人格资料与分类回复语料，支持可保存的玩家消息和即时好友回复。
- 双击联系人可靠地进入对应会话，消息页原有单击入口继续可用。
- 新存档获得若干条由既有朋友圈模板确定性抽取的初始内容。

**Non-Goals:**

- 不接入大语言模型、网络聊天、输入审核或真实微信协议。
- 不实现延迟回复、正在输入、语音、图片发送、红包、评论与点赞。
- 不一次性替换全酒吧环境、角色动画和所有占位素材。
- 不改变现有配方评价、经济结算或粒子流体业务口径。

## Decisions

### 1. 视觉引用仍属于内容定义

给调酒内容基类增加可选 `icon_texture: Texture2D`，具体 `.tres` 直接引用运行时 PNG；`asset_id` 继续承担存档、清单和替换契约。这样工作台只读取通用字段，不新增 `moon_gin` 等具体 ID 分支。相比运行时解析 JSON 清单，Resource 引用能让 Godot 导入依赖、编辑器预览和缺失资源诊断更直接。

### 2. 长柄勺由工作台统一捕获全局拖拽

器具按钮仅开始手势，工作台 `_input` 在拖拽期间持续更新跟随鼠标的视觉和轨迹；释放时同时检查混合容器命中、容器开放、轨迹路程与持续时间。只有所有条件满足才向既有输入路由提交通用 `stir` 命令。相比依赖按钮的 `gui_input`，全局捕获不会因鼠标离开按钮而丢失事件，也便于 headless 注入测试点位。

### 3. 联系人人格与回复语料全部配置化

`WechatContactDefinition` 增加简介、兴趣、爱好、人格、回复风格、口头禅，以及问候/提问/兴趣/普通四类回复模板。回复生成器只读取这些字段，根据输入关键词分类，再通过稳定种子与消息序列选择模板；不在 UI 内写角色分支。离线规则回复可重复测试、无隐私和联网风险，后续若引入更复杂系统仍可把同一配置作为角色上下文。

### 4. 聊天序列与社交事件游标分离

`WechatState` 增加独立 `next_message_sequence`；玩家消息与秒回消耗消息序列，但不改变外围事件随机游标。消息实例增加 `from_player`，既有存档缺省为好友消息。这样玩家多发一句话不会改变下一次订单事件会抽到哪条朋友圈。

### 5. 初始朋友圈只在新状态创建时生成

服务初始化空状态时，以固定基础种子和递增游标从模板中生成目标数量的初始朋友圈并保存实例；从存档恢复时不重复引导生成。这里的“随机”是对玩家可见的内容抽取，而不是不可复现的系统随机。

### 6. 双击作为联系人页显式导航手势

联系人条目使用 Button 并监听 `InputEventMouseButton.double_click`；双击后切换消息页并打开联系人会话，单击只提供选中反馈，不误触导航。消息摘要仍保持单击打开，兼容原有使用习惯。

### 7. 大厅采用生成背景与程序化交互覆层

根据参考图重新生成一张不含品牌文字与主体角色的原创大厅背景，作为 `CatBarWorldView` 的底层纹理；热点边框、吧台引导灯、桌面烛光和区域名称继续由 Godot 程序化绘制。相比把交互直接烘进大图，这种分层方式既获得完整氛围，又能在替换背景时保持点击区域、角色路径和状态反馈稳定。

### 8. 手机使用共享的代码化像素主题

在 `features/phone/presentation/` 提供无状态样式工厂，为手机壳、应用入口、微信页签、联系人、消息气泡和朋友圈卡片统一创建直角/小圆角深色面板、暖金描边、木棕层次与微信绿强调色。样式不写入领域数据，不改变布局职责；代码化主题比生成一整张手机皮肤更能适应动态文本和列表长度。

## Risks / Trade-offs

- [生成图像尺寸远大于逻辑像素网格] → 使用 nearest filtering、等比缩放和清单尺寸登记；生成图作为开发期原创素材并保留审阅状态。
- [大厅背景可能与实际热点位置略有偏差] → 生成时固定中央吧台和前景三卡座构图，并用程序化高亮覆盖真实热点。
- [规则秒回可能重复或显得机械] → 每联系人提供多类模板和口头禅，选择由独立消息序列变化，未来可扩充而不改 UI。
- [双击对触屏不友好] → 本轮目标平台是 Windows 鼠标；消息页仍提供单击入口，后续可增加长按或详情按钮。
- [拖拽轨迹阈值让玩家困惑] → 拖拽时高亮容器，失败时分别提示未放入容器、轨迹不足或容器已封闭。
- [存档字段扩展导致旧历史方向不明] → 缺失 `from_player` 一律按好友消息迁移，并从历史最大序号重建下一消息序列。

## Migration Plan

1. 扩展 Resource 与运行时状态字段，保持所有新字段有安全默认值。
2. 更新默认内容配置、资产清单和 UI；旧 `.tres` 未配置图标时仍显示文字占位。
3. 读取 v2 存档时补齐消息方向和消息序列，不更改已有文本、作者、时间与已读状态。
4. 通过领域、场景、资产、存档及 headless 全套测试后合并规格并归档 change。

回滚时可移除新 UI 入口而保留新增存档字段；加载器会忽略未消费的兼容字段，不需要破坏旧存档。
