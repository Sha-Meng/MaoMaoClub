## REMOVED Requirements

### Requirement: 分类式吧台内容菜单

调酒台不再以独立的一级、二级菜单作为主要交互入口。

#### Scenario: 进入调酒模式

- **WHEN** 玩家进入调酒模式
- **THEN** 系统不显示“基酒、工具、辅料”分类菜单
- **AND** 玩家改为直接操作场景物件

## ADDED Requirements

### Requirement: 场景内实体操作

调酒呈现层 MUST 在镜头拉近后的同一场景画面中展示可交互原料和工具，并 MUST NOT 要求玩家打开独立的全屏调酒菜单。

#### Scenario: 基酒量取并转入 Shake 杯

- **当** 玩家拖起任一基酒瓶
- **那么** 量酒器显示引导描边
- **并且当** 玩家在量酒器上释放
- **那么** 系统播放酒瓶倾倒动画，并在动画确认点把该基酒的固定剂量写入量酒器
- **并且当** 玩家把非空量酒器拖到 Shake 杯释放
- **那么** 系统播放量酒器倾倒动画，将量取内容转入 Shake 杯并更新杯内液体表现

#### Scenario: 查看物件与容器信息

- **当** 指针悬停基酒或辅料
- **那么** 局部信息卡显示物件名称、类别、默认剂量和风味信息
- **当** 指针悬停 Shake 杯
- **那么** 信息卡显示当前内容物、每种内容的毫升数和总量

#### Scenario: 封盖并完成 Shake

- **当** 玩家拖起杯盖
- **那么** Shake 杯显示合法目标描边
- **当** 玩家在有内容且未封盖的 Shake 杯上释放杯盖
- **那么** 杯盖贴合杯口，Shake 杯显示就绪描边并播放轻微抖动
- **当** 玩家按住已封盖 Shake 杯并上下左右移动
- **那么** 系统采样 Shake 轨迹，同时把可视位移限制在吧台工作范围内
- **当** 玩家松开 Shake 杯
- **那么** 系统提交本次 Shake 的时长、距离、反向次数和峰值速度

#### Scenario: 倒入成品杯

- **前提** 当前 Shake 已有效完成
- **当** 玩家拖起 Shake 杯
- **那么** 成品杯显示合法目标描边
- **当** 玩家在成品杯上释放
- **那么** 系统播放倒杯动画，提交出杯命令并进入既有配方判定与送餐流程

#### Scenario: 非法释放

- **当** 玩家在合法目标外释放任何物件，或当前状态不允许该操作
- **那么** 物件回弹原位并显示明确原因
- **并且** 调酒会话草稿不得发生改变
