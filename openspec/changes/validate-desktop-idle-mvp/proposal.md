# validate-desktop-idle-mvp

## 为什么要做

MaoMaoClub 需要先验证桌面挂机陪伴体验是否成立。玩家打开游戏后，应该能在桌面边缘看到一个持续运转的小酒馆：猫猫会走动、被点击、被拖拽到岗位；顾客会从右侧出现、到酒摊点酒、坐下喝酒、聊天、离开；成功消费会带来金币和经营值反馈。

这个 MVP 先不追求完整经营深度。它要回答的问题是：

- 这个游戏作为桌面常驻小世界是否有陪伴感？
- 猫猫拖拽上岗是否直观、好玩、可反复操作？
- 顾客进店、消费、离开的动线是否清楚？
- 玩家是否能从基础收益反馈里理解“酒馆正在营业”？

## 改动内容

- 新增“桌面挂机体验”规格，用来定义第一个 MVP 的玩家可见行为。
- 创建一个薄主场景承载的桌面小酒馆原型场景。
- 使用占位资源实现酒摊、座椅区、三只猫猫、三类顾客、金币和经营值反馈。
- 实现猫猫的待机、随机走动、点击、拖拽、投放到酒摊岗位、上岗工作状态。
- 实现顾客从右侧进入、点酒、找座位、喝酒或聊天、向左离开的基础链路。
- 实现成功卖酒后的金币与经营值增长。
- 暂不实现调酒研发、今日菜单策略、抽猫、繁育、DJ、驻唱、钢管舞台、联网涂鸦墙和长期熟客剧情。

## 落地方式

1. 场景落地：新增桌面小酒馆 MVP 场景，由 `res://scenes/main.tscn` 进入或承载，主场景只负责启动与路由。
2. 功能目录：按 基于功能组织 方式拆到未来的 `features/desktop_idle/`、`features/cats/`、`features/customers/`、`features/economy/`。
3. 数据先行：先用简单配置定义三只猫、三类顾客、基础订单收益和基础停留时间，避免把数值写死在多个节点里。
4. 交互闭环：优先完成“拖猫上岗 -> 顾客消费 -> 金币/经营值变化”这条最短闭环。
5. 表现增强：在闭环跑通后补充待机动作、聊天气泡、收益飘字、岗位高亮等可读性反馈。
6. 验收 试玩验证：在 Godot 4.6.3 稳定版 中连续运行，观察猫猫、顾客、收益是否能稳定循环。

## 影响范围

- 规格：`desktop-idle-experience`
- 未来代码：`features/desktop_idle/`、`features/cats/`、`features/customers/`、`features/economy/`、主场景路由
- 验证：Godot 4.6.3 手动试玩，配合 带类型标注的 GDScript、显式返回类型、基于功能组织 目录检查
